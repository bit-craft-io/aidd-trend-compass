# brainstorming 持ち込み資料

新しい企画・改修を `/superpowers:brainstorming` に持ち込む前に、このテンプレートをコピーして埋めておく。
埋めた内容をそのまま貼り付けて brainstorming を開始すると、対話がスムーズに進む。

## 目標・動機

株価の「予測」ではなく、マクロ(業界・市場全体)とミクロ(個別銘柄)を繋ぎ、
過去データ・ニュース・市場分析に基づく「傾向」を、根拠を示しつつ控えめに提示する
補助アプリを作る。

既存の「株価予測アプリ」の多くは断定的中を装いがちであり、短期の値動きは
本質的に予測不能である以上、誠実さを欠く。本アプリは「予測」ではなく
「判断材料の整理・助言」を主軸とし、利用者自身の判断を支える立ち位置を取る。

アプリ名: 株価羅針盤

## 主要な機能・画面

### 1. 一覧画面(Main)
- 株式コード入力 + 取得ボタン(銘柄をウォッチリストへ追加)
- ウォッチリスト
  - チェックボックス(個別・全選択/全解除)
  - 株式コード
  - 会社名
  - 所見(「数字を先に示し、控えめな言葉を添える」型の一行要約。例:「直近5日+2.3%、業種平均を上回る」)
  - 詳細ボタン(→詳細画面へ遷移)
  - 削除ボタン
- 更新間隔選択(1分/5分/10分/15分) + 更新ボタン

### 2. 詳細画面(Detail)
- 単一銘柄について、分析に用いた生データを「見るだけ」で表示する画面(操作要素なし)
- 履歴データ: ローソク足チャート、移動平均線、直近60日高値・安値、出来高
- 市場分析: 業種指数、業種平均との相対強度、マクロ指標(金利・為替等)との相関
- 最新ニュース: 見出し・センチメント判定(ポジティブ/中立/ネガティブ)・掲載時刻

## テーブル(DB)設計の叩き台

### trend
- id = Auto Increment（unsigned big int）
- code = 株式コード
- name = 会社名
- opinion = 所見
- detail = 取得データ（JSONで保存。ローソク足等の描画に用いる生データ一式）
- price_at_fetch = created_at 時点の価格（前回取得との差分表示に用いる）
- created_at = 作成日付
- updated_at = ORM慣習によるデフォルト項目（本テーブルでは実質未使用）
- deleted_at = 論理削除日付。「更新」ボタン押下時、更新間隔(created_at)を超過した
  対象codeの旧データにのみ日付が入り、之がそのまま過去の履歴として残る

**運用の要点(確認済み)**
- 「更新」ボタン押下時、選択中の更新間隔を created_at が超過している行のみ、
  新規行を追加取得する
- 同時に、旧い方の行(同一code)には deleted_at を入れる。
  之は物理削除ではなく、履歴として保持したまま「現在の最新ではない」ことを示す
  ソフトデリートの仕組みなり(履歴テーブルを別途持たず、trend 1本で
  現在値と履歴を兼ねる設計)
- code/name(基本情報)と opinion/detail/price(分析結果)の非正規化は、
  現段階では意図的な選択(後々、機能拡張の折に見直す)

## 技術的な制約

### スタック
- フロントエンド: React(SPA)
- バックエンド: Python / FastAPI(履歴データ取得・センチメント分析・
  テクニカル指標計算をまとめて担う)
- DB: MySQL
- 動作環境: Docker(自身のローカル環境で完結させる想定。多数への公開は想定せぬ)

### 履歴データ取得
- yfinance(Python製、非公式ライブラリ)を候補とする
- FastAPI側でyfinanceを直接呼ぶ構成とし、Node.js/Pythonの言語跨ぎの問題は
  之にて解消済み
- Yahoo!の利用規約上「個人利用のみ」を意図する旨の明記あれど、本アプリは
  自身のローカルDocker環境で完結させる想定にて、此処は問題とならず

### テクニカル指標
- 移動平均・ボリンジャーバンド等は、外部APIに頼らずローカルロジックで計算する方針
- 計算はFastAPI(Python)側でpandas-taを用いて行い、Reactは算出済みの値を
  受け取ってチャート描画するのみとする(フロント側での再計算は行わぬ)

### ニュース・センチメント分析
- ニュース見出しをClaude APIへ直接渡し、センチメント判定させる方式を第一候補とする
  (専用センチメントAPIは無料枠が狭いものが多いため)
- 見出し自体の取得元、及びセンチメント分析の実装詳細は、改善の段にて再検討する

### 設計方針・文言
- UIの文言は「数字を先に示し、その上で控えめな言葉を添える」型を徹底し、
  断定調(「上がります」等)を用いない
- 「予測」ではなく「傾向分析・助言」であることを、随所で利用者に伝える設計とする

### 開発体制
- `.claude/rules`、`.claude/skills` に、上記の設計方針を明文化し、
  Claude Codeでの実装時に一貫させる
  - `trend`テーブルの`opinion`(所見)は、断定調を用いず
    「数字を先に示し、控えめな言葉を添える」型に従う旨をルール化する

### 画面設計
- モックアップはClaudeのDesign artifact(canvas)にて作成済み
  (一覧画面: `docs/images/level-01-top_20260917_14.png`、
  詳細画面: `docs/images/level-02-detail_20260917_14.png`)

## 追加検討候補(未brainstorming, 2026-09-18時点、機能A/B/横断的UI基盤 実装完了後の拡張案)

機能A・機能B・テーマ設定(横断的UI基盤)は実装完了・main統合済み。以下は
TradingView(https://jp.tradingview.com/)の機能を参考に出た、機能Bの延長として
brainstorming前に整理しておく生の材料。

### TradingView参考機能(抜粋3件)

- **アラート**: 価格・指標条件を満たした際の通知。機能A(一覧・更新間隔)の延長として
  検討
- **テクニカル指標の選択式追加**: 現状は5日移動平均(SMA5)のみ。RSI/MACD等を
  任意選択で追加できる形を機能Bの延長として検討
- **経済カレンダー**: 決算日・経済指標発表日の表示。機能C(ニュース/センチメント、
  未着手)との親和性を検討

TradingViewのPine Script(カスタム指標記述)・スクリーナー・ブローカー連携・
コミュニティ機能(アイデア共有)は、個人ローカル利用+断定調回避という本アプリの
方針と乖離が大きいため対象外とする方向

### 足種(タイムフレーム)切替

現状、詳細画面の履歴データは日足のみ(直近90日、機能Bのdoc-spec 02参照)。
以下の足種への切替機能を検討:

- 追加候補: 5分足、10分足、15分足、日足、週足、月足
- 対象外(見送り): 1分足 — yfinance側の取得可能期間が直近7日分のみと短く、
  実用上の価値が薄いため

**技術メモ(検証済み)**:
- yfinanceがネイティブ対応するinterval: `1m, 2m, 5m, 15m, 30m, 60m, 90m, 1d, 1wk,
  1mo` 等。**10分足はYahoo Finance API自体が非対応**のため、5分足を取得した上で
  backend側でpandasの`resample("10min")`によりOHLC集計して合成する
- 分足(5分・15分)はyfinance側の制限で直近60日分までしか取得不可。日足・週足・
  月足はこの制限を受けない
- 常時自動更新(一覧のリフレッシュ処理)には乗せず、詳細画面でユーザーが足種を
  選択した際にオンデマンドでbackendへ問い合わせる方式を想定(過去、yfinance/
  Yahoo Finance側の429レート制限に実際に遭遇した経緯があるため、常時監視型の
  負荷増は避ける)
- UI上、足種ごとに表示可能な期間が異なる旨(例:「5分足は直近60日分のみ表示可」)
  を明示する必要あり
