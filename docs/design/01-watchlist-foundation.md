## 機能概要

株価羅針盤の基盤(Docker/DB/API/React土台)と、一覧画面(Main)を実装する。
ユーザーは株式コードを入力してウォッチリストへ銘柄を追加し、一覧で各銘柄の
現在値・所見を確認、任意のタイミングで再取得(更新)、不要な銘柄を削除できる。
この機能の完成時点で「価格+簡易所見のみが見える」MVPが動く状態を目指す。

## 実装背景

既存の「株価予測アプリ」は断定的中を装いがちで誠実さを欠く。本アプリは
「判断材料の整理」を主軸とし、利用者自身の判断を支える。その最初の入口として、
ウォッチリストを軸にした一覧画面を用意する。詳細な企画背景は
`docs/brainstorming-intake.md` を参照。

## 影響・対象範囲

- 新規プロジェクトのため既存コードへの影響は無い
- 対象: Docker Compose構成一式、`trend`テーブルのスキーマ・マイグレーション、
  一覧画面に関するAPI(取得・一覧取得・更新・削除)、一覧画面のReact実装
- 対象外(機能B/Cへ持ち越し): 詳細画面の中身(履歴チャート・市場分析・ニュース)

## ゴール

- 株式コードを入力→取得ボタンでウォッチリストに追加できる
- ウォッチリストに現在値・所見・会社名が表示される
- 「更新」ボタン押下で、選択(チェック)中の銘柄のうち、更新間隔を過ぎたものだけ
  再取得され、一覧に反映される
- 「削除」ボタン押下で銘柄がウォッチリストから消え、再度同コードを取得すれば
  復活できる(履行データは物理削除せず保持する)

## 対象外

- 詳細画面の実装(機能B/Cで扱う)
- 認証・ユーザー管理(本アプリはローカルDocker環境での個人利用のみを想定し、
  実装しない)
- テクニカル指標計算・ニュース取得・センチメント分析(機能B/Cで扱う)

## 解決策・技術アーキテクチャ

### 全体構成

Docker Compose 3コンテナ: `frontend`(React/Vite)、`backend`(FastAPI)、
`db`(MySQL)。フロントはbackendのREST APIのみを叩く。yfinance呼出は
backend内で完結させる(言語跨ぎの問題を回避)。

### DBスキーマ

`docs/brainstorming-intake.md` の `trend` テーブル叩き台をそのまま採用する。

- `id`, `code`, `opinion`, `detail`(JSON), `price_at_fetch`,
  `created_at`, `updated_at`, `deleted_at`
- `daily_trend`(日足のトレンド。`up` / `down` / `flat`、判定できないときはNULL。
  取得・更新のときに計算して保存する。トレンドの定義と閾値は09参照)
- 銘柄名は`trend_code_name`で管理する(08参照)
- `deleted_at` は物理削除ではなく「現在の最新ではない」ことを示すソフトデリート。
  以下2つのケースで両方使う(同じ意味として扱う):
  - 更新間隔を過ぎた旧データに対し、新規行追加と同時に旧行へ設定
  - ウォッチリストから削除された銘柄の最新行に対して設定(削除ボタン押下時)
- 一覧表示クエリは「code単位でdeleted_at IS NULLの行が存在するもの」を対象とする。
  削除後に同コードを再取得すると新規行がinsertされ、再び表示対象になる

### API(backend / FastAPI)

- `POST /trends` — コードを受け取り、yfinanceから会社名・現在値を取得しinsert。
  無効コードの場合は404を返す
- `GET /trends` — deleted_at IS NULLの最新行一覧を返す
- `POST /trends/refresh` — チェック済みcodeのリストと選択中の更新間隔を受け取り、
  created_atが間隔を超過している対象のみ新規行insert+旧行deleted_at設定
- `DELETE /trends/{code}` — 対象codeの最新行(deleted_at IS NULL)にdeleted_atを設定

### コンポーネント(frontend)

- `WatchlistPage` — 画面全体。state: `watchlist[]` / `selectedCodes: Set` /
  `interval`(1/5/10/15分、初期値1分)。いずれもReact stateのみで保持し、
  詳細画面への遷移・復帰時もSPA内ルーティングのため消えない
  (ページリロード時のみリセットされる想定で良い)
- `useWatchlist` — 一覧取得・追加・更新・削除のAPI呼出をまとめるhook
- コード入力欄 — 取得ボタン押下時、無効コードならバックエンドの404を受けて
  入力欄直下にインラインで赤字エラーメッセージを表示する

### データフロー

1. 取得: コード入力→`POST /trends`→成功時一覧再取得、失敗時インラインエラー表示
2. 更新: 「更新」押下→チェック済みcode一覧+選択中intervalを`POST /trends/refresh`
   へ送信→バックエンドで間隔超過分のみ新規insert+旧行deleted_at設定→
   フロントは一覧再取得
3. 削除: 「削除」押下→`DELETE /trends/{code}`→一覧から即時除外

### エラー処理

無効コード・ネットワークエラーは全て入力欄直下のインラインメッセージで通知する。
専用のトースト等は導入しない。

### テスト方針

- backend: pytestで`trend_service`のソフトデリート判定ロジック(間隔超過判定・
  削除時のdeleted_at設定)を重点的に単体テスト。yfinance呼出はモックする
- frontend: vitest + React Testing Libraryで、取得・チェック選択・更新・削除の
  主要フローをコンポーネントテストで確認
