## 機能概要

一覧画面に、保有ポジション情報(購入金額・購入株数・預かり区分・損益)の入力・表示と、
銘柄をグループ単位で整理する機能(グループ作成・選択・絞込)を追加する。あわせて、
会社名の表示を英語名からニックネーム(日本語名など任意の表示名)へ切り替え可能にする。

## 実装背景

一覧画面(機能A)は現状、現在値と所見のみを表示する構成になっている。実際に保有して
いる銘柄については、購入時の金額・株数を踏まえた損益を一覧で把握したいという要望が
ある。また、銘柄数が増えるにつれ、任意の観点(業種・戦略等)でグループ分けし、絞り
込んで閲覧したいという要望もある。本doc-specは機能Aの直接の延長として、これらを
一覧画面へ追加する。

## 影響・対象範囲

- 対象: 会社名の表示名(`trend_code_name.name`。08で一元化)の入力欄追加、`trend_price`/`trend_group`テーブルの
  新規追加、一覧画面(`WatchlistPage`/`WatchlistTable`)関連APIの拡張、一覧画面の
  React実装拡張
- 対象外:
  - 詳細画面側への購入情報・損益の反映(将来必要になれば別途doc-spec化)
  - `buy_category`以外のenum種別が増えた際の、typeを汎用的に扱う共通マスタテーブル化
    (今回は`buy_category`固定のenumとして実装し、種別が増えた時点で改めて検討する)

## ゴール

- ウォッチリストの各銘柄に、預かり区分(特定/一般/NISA)・購入金額・購入株数を入力
  でき、DBに保存される
- 損益((現在値-購入金額)×購入株数)が入力の都度、画面上に即座に反映される
- 会社名をニックネーム(任意の表示名、主に日本語名を想定)で表示できる。自動取得
  できない場合は手動入力で補完できる
- グループを作成し、各銘柄にセレクトボックスから紐付けられる
- グループで一覧を絞り込める

## 対象外

- 詳細画面の実装への波及
- 認証・ユーザー管理(本アプリの既定方針どおり実装しない)
- `buy_category`以外のenum種別増加時の共通マスタ化

## 解決策・技術アーキテクチャ

### DBスキーマ

**会社名の表示名**

- 会社名の表示名は`trend`テーブルには持たず、`trend_code_name.name`(08で一元化)で
  管理する。銘柄取得時(`POST /trends`)に自動取得できる情報源があれば保存し、無ければ
  空のまま作成する。一覧画面から後追いで編集・保存できる

**`trend_group`テーブル(新規)**

- `id` (PK, auto increment)
- `name`
- `created_at`
- `updated_at`
- `deleted_at` (ソフトデリート)

**`trend_price`テーブル(新規)**

- `id` (PK, auto increment)
- `code` (`trend.code`に対応、UNIQUE制約、FK制約なし・アプリ側で整合性管理)
- `trend_group_id` (NULL許容、FK制約なし)
- `buy_category` (TINYINT, NOT NULL, DEFAULT 0 — 0:未選択, 1:特定, 2:一般, 3:NISA)
- `buy_price` (購入単価)
- `buy_quantity` (購入株数)
- `created_at`
- `updated_at`
- `deleted_at` (ソフトデリート。`trend`テーブルのような履歴保持(行の複製)は行わず、
  購入金額・株数・預かり区分・グループの変更は既存行へのUPDATEで行う。銘柄削除時に
  `deleted_at`を設定し、再度同じ銘柄を取得した際は同じ行を復活(`deleted_at`をNULLに
  戻す)させ、行を増殖させない)

**グループ削除時の扱い**

`trend_group`をソフトデリートしても、紐付く`trend_price.trend_group_id`は変更しない
(データ操作を行わない)。一覧表示時にLEFT JOINでグループが取得できない(ソフト
デリート済み)場合は、フロントエンド側で「グループを選択」(未選択と同じ表示)に
フォールバックする。

### API(backend / FastAPI)

- `GET /trends` — レスポンスに`name`(`trend_code_name.name`)、`trend_group_id`、`buy_category`、
  `buy_price`、`buy_quantity`を追加(既存の現在値・所見等はそのまま)
- `PATCH /trends/{code}/name` — 会社名(`trend_code_name.name`)の編集保存
- `POST /trend-groups` — グループ作成
- `GET /trend-groups` — グループ一覧取得(`deleted_at IS NULL`)
- `DELETE /trend-groups/{id}` — グループのソフトデリート
- `PATCH /trend-prices/{code}` — `trend_group_id`/`buy_category`/`buy_price`/
  `buy_quantity`をまとめて更新。対象の`trend_price`行が存在しなければ新規作成、
  ソフトデリート済みなら復活させてから更新する

### コンポーネント(frontend)

- `WatchlistPage`のコントロール行(既存の1段構成を維持したまま要素追加):
  株式コード入力+取得ボタン / グループ名入力+作成ボタン+削除ボタン /
  グループ絞込セレクト+絞込ボタン(既存の更新ボタンと同じ配色) / 更新間隔+更新ボタン
- `WatchlistTable`の列構成: チェックボックス / グループ(セレクト) / 更新日時 /
  コード / 会社名(`trend_code_name.name`) / 現在値 / 預かり区分 / 購入金額(入力) /
  購入株数(入力) / トレンド / 損益 / 操作(意見・詳細・削除の3つのボタン。意見の定義は09参照)
- `WatchlistTable`の右側に、「AIによる3つの目線」のパネル(`PerspectivesPanel`)を置く。行の「意見」を
  押した銘柄の、買い・売り・キープの3つの目線を出す。開いている間、一覧は主要な列だけに折りたたむ。
  結果は`trend`に保存する(定義は09参照)
- トレンド列と行の色: 日足のトレンド(`trend.daily_trend`。定義と閾値は09参照)を表示する。
  行の色は、上昇=赤っぽい、下降=緑っぽい。横ばい・判定なし(「—」)は色なし
- 損益計算: `buy_price`・`buy_quantity`の入力`onChange`ごとにクライアント側で
  `(現在値-購入金額)×購入株数`を再計算し、画面表示を即時更新する
  (DBへの保存とは分離)
- 保存タイミング: 預かり区分・購入金額・購入株数・グループ選択は、入力欄の`onBlur`
  でAPI保存する。Enterキー押下時は`input.blur()`を発火させて同じ経路で確定させる。
  直前に保存した値との差分が無ければAPI呼出しをスキップする
- グループ絞込: セレクトの変更だけでは一覧に反映せず、「絞込」ボタン押下時に
  選択中グループで一覧をフィルタする(更新間隔+更新ボタンと同じ「選択→ボタンで
  確定」の操作パターンに揃える)

### データフロー

1. 銘柄取得: 既存フロー(`POST /trends`)を維持。取得時に`trend_code_name.name`の自動取得を
   試みる
2. ポジション編集: 預かり区分/購入金額/購入株数の入力→`onBlur`または`Enter`→
   直前値との差分確認→差分があれば`PATCH /trend-prices/{code}`→成功時は既存表示を
   維持(損益は既にクライアント側で反映済みのため再取得不要)
3. グループ作成: グループ名入力→作成ボタン→`POST /trend-groups`→グループ
   セレクトの選択肢へ反映
4. グループ紐付け: 行のグループセレクト変更→`PATCH /trend-prices/{code}`
5. グループ絞込: セレクト変更→「絞込」ボタン押下→選択中`trend_group_id`で
   一覧をクライアント側フィルタ
6. 意見: 行の「意見」ボタン→保存済みならそれを表示。無ければ`POST /trends/{code}/perspectives`→
   一覧の右側のパネルに表示(`trend`に保存する。失敗したときは保存しない)

### エラー処理

既存方針を踏襲し、専用のトースト等は導入しない。ポジション編集・グループ操作の
API呼出しが失敗した場合も、該当行/コントロール直下にインラインで赤字エラー
メッセージを表示する。

### テスト方針

- backend: pytestで以下を重点的に単体テストする
  - `trend_price`のUPDATE中心ロジック(新規作成・既存行の値更新・ソフトデリート・
    再取得時の復活)
  - `trend_group`のCRUD(作成・一覧・ソフトデリート)
  - グループ絞込クエリ
  - `trend_group`がソフトデリート済み(削除済み)の場合でも、紐付く`trend_price`を
    持つ銘柄が一覧取得(`GET /trends`)で正しく返される(グループ情報のみ欠落し、
    銘柄自体は表示対象から漏れない)こと
- frontend: vitestで以下をコンポーネントテストする
  - 購入金額・購入株数入力時の損益即時計算・表示
  - blur保存時の差分無しスキップ挙動
  - Enterキー押下時の確定挙動
  - グループ絞込ボタン押下による一覧フィルタの確定挙動(セレクト変更のみでは
    フィルタされないこと含む)

## 追記: AIDDK-3 売却価格(予定)の入力・保存(2026-10-09)

Jira: AIDDK-3(親エピックは AIDDK-17「画面:保有一覧」)。元の本文は、書き換えない。この節が、あとの合意として、有効になる。

- **目的**: 売り時の目安として、銘柄ごとに、売却したい価格(予定)を、一覧で入力し、保存する
- **意味**: 1株あたりの価格(購入金額`buy_price`と同じ)
- **DB**: `trend_price`に、列`sale_price_target`(`Numeric(12,2)`、NULL許容、既定はNULL)を足す。
  列の並びは、`buy_quantity`の次。既存の行は、NULL(未設定)。
  マイグレーション機構が無いため、既存のDBへの反映は、DBの作り直し(`docker compose down -v`)で行う
- **API**:
  - `PATCH /trend-prices/{code}`: リクエストとレスポンスに`sale_price_target`(数値またはNULL)を足す。
    入力の検査は、`buy_price`と同じ(NULL許容。数値以外は、フロントが、NULLとして送る)
  - `GET /trends`: 各項目に、`sale_price_target`(数値またはNULL)を足す
- **画面**:
  - 見出しは「売価(予)」(幅を詰めるため。名称は、売却価格(予定)。入力欄の読み上げ用の名称`aria-label`は、「売却価格(予定)」)。列の位置は、「購入株数」の右、「トレンド」の左
  - 入力の振る舞いは、購入金額と同じ(`onBlur`で保存、Enterで確定、直前の保存値と同じなら、API呼出しをスキップ。空欄は未設定)
  - 意見のパネルを開いて、一覧を主要な列だけに折りたたむときは、他の副次の列と同じく、隠す
- **範囲外**: 売却価格(予定)で見込む損益(想定損益)の計算・表示。別のタスクにする
- **変更する元の記述**:
  - 「データ」の、`trend_price`の列の一覧(`buy_quantity`の次に`sale_price_target`)
  - `GET /trends`・`PATCH /trend-prices/{code}`の項目(`sale_price_target`を足す)
  - `WatchlistTable`の列構成(「購入株数(入力)」と「トレンド」の間に、「売価(予)(入力)」)
  - 保存タイミングの対象(預かり区分・購入金額・購入株数・グループ選択に、売却価格(予定)を足す)

## 追記: AIDDS-19 入力項目のラベル表示(2026-10-19)

Jira: AIDDS-19(親エピックは AIDDS-9)。判断の記録: [ADR-0006](../decisions/adr-0006-click-to-edit-inline-fields.md)。元の本文は、書き換えない。この節が、あとの合意として、有効になる。

- **対象**: 保有一覧の、グループ、会社名、預かり区分、購入金額、購入株数、売価(予)。発掘一覧は、入力する項目が無い(行のチェックボックスのみ)ので、変えない
- **表示(通常時)**:
  - 値を、枠線つきのラベルで表示する。入力欄は、出さない。表示と編集で、幅と高さを同じにする
  - 値が空の、会社名・数値の項目は、「—」。選択式で、選ばれていない状態は、「未選択」(グループ、預かり区分)
  - 数値は、素の数字のまま(桁区切り・通貨記号は、付けない)。長い会社名は、枠の幅で、省略記号(…)で切る(編集中は、全体が見える)
- **編集へ入る**:
  - ラベルを、クリックする、または、Tab で着くと、その項目だけが、編集に切り替わる。切り替わると、フォーカスが当たる
  - 編集は、グループと預かり区分が、セレクトボックス。会社名と数値が、テキストボックス
  - セレクトボックスは、切り替えと同時に、`showPicker()` でリストを開く。対応しない、許可されない、または、例外が出る環境では、リストは開かない(もう1回クリックで開く)。Tab で着いたときも、開かなくてよい
  - 編集中に、行のデータが更新されても、入力中の値を保つ
- **数値欄の入力**: 半角の数字(0〜9)だけ。文字、全角の数字は、入らない。購入金額・売価(予)は、小数点を扱わない(整数のみ)。購入株数は、マイナスを扱わない
- **確定と保存**:
  - テキストボックス: フォーカスが外れる、または、Enter で確定する。日本語入力の、変換の確定の Enter は、変換を確定するのみ(保存の確定は、そのあとの Enter)
  - セレクトボックス: 値を選んだ時点で確定する
  - 確定すると、ラベルに戻る。値が変わっていれば、保存する(API・保存の条件は、これまでと同じ)。変わっていなければ、保存しない
  - Esc: 入力を捨てて、ラベルに戻る。保存しない。戻るとき、フォーカスは、ラベルへ返さない
  - 保存に失敗したときは、行のエラーを出し、ラベルは、保存前の値に戻る
- **アクセシビリティ**: ラベルと、編集欄に、同じ `aria-label`(「{コード}の購入金額」など)を付ける
- **変更する元の記述**:
  - 保存タイミングの対象の記述(「`onBlur`で保存、Enterで確定」。購入金額・購入株数・預かり区分・グループ選択、AIDDK-3 の売却価格(予定))。入力欄が常に出ている前提を、「クリックで編集に入る」に変える。保存の条件は、変えない
  - AIDDK-3 の節の「入力の振る舞いは、購入金額と同じ」: 売価(予)も、同じ、ラベル表示+クリックで編集
  - グループの未設定の表示(選択肢の文言「選択」): 「未選択」に変える
  - 損益の表示(「購入金額・購入株数入力時の損益即時計算・表示」): 入力の途中では更新せず、購入金額・購入株数を確定したときに、更新する(ラベル表示では、入力の途中の値を、持たないため)
- **範囲外**: 数値の桁区切り・通貨記号の表示。小数の単価の入力。保有一覧以外の入力欄(コードの入力、グループ絞込、更新間隔など、一覧の外の入力)は、変えない(ADR-0006: 対象は、一覧の中のセレクトボックス・テキストボックス)
