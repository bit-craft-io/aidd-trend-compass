# ADR-0005: 発掘と一覧のトレンドの食い違いは、列見出しの添え書き(常に表示)で示す

> **遡及作成(2026-10-08)**: 本ADRは、決定の後に、設計書と計画書の記述から書き起こした。仕様の本体は、設計書に有る(ここには書き写さない)。出典で確認できない点は「要確認」と記す。

## ステータス

提案中

## 背景・課題

同じ銘柄で、発掘は `up`、保有一覧は `down` のように、食い違うことがある。判定の式(`classify_trend`)は同じだが、入力のデータが違うため(発掘: J-Quants の日足の終値。一覧: yfinance の5分足を日足にまとめた終値)。値の時点も違う(発掘: 表示のとき。一覧: 取得・更新のとき)(設計書09の末尾の節)。

## 決定

- 「トレンド」列の見出しの下に、小さな文字で、2行の添え書きを付ける。常に表示する(AIDDS-18、案C)
  - 発掘: 「J-Quants 日足」「60営業日」
  - 一覧: 「5分足を日足に」「更新時の値」
- 見出しの高さは3行以内。列幅は、原則として変えない(添え書きのためにだけ、広げてよい)
- 一覧で、意見のパネルを開いて列を折りたたんだときは、添え書きを出さない
- ライト・ダークの両方で読める文字色にする

仕様の詳細: [設計書 09](../design/09-trend-direction-and-market-colors.md)の末尾の節(AIDDS-18)。確認の記録: [計画書](../superpowers/plans/2026-10-01-AIDDS-9-feature-improvement-202610-01.md) の「追記: AIDDS-17・AIDDS-18 の確認してほしい点」の7(確認済み)。

## 検討した代替案

- **吹き出し(ⓘ)で示す**: 採らなかった(設計書09、計画書)。採らない理由は、記録に無い(要確認)
- **ヘルプモードを追加し、オンのときだけ、添え書きを表示する**: 今回の範囲外(設計書09)。理由は、記録に無い(要確認)
- **データを、そろえて、食い違いをなくす**: 記録に無く、検討したかどうかも不明(要確認)

## 影響・トレードオフ

- 見出しが、3行になり、画面の縦と横を、少し使う
- 食い違いそのものは、なくならない。説明を足しただけ
- 範囲の表記は「60」に固定した。実際は、90営業日分を取得する場合がある。判定に使うのは、直近26本の終値だけで、範囲の長さは、結果に影響しない(設計書09)
- 見直す兆候: ヘルプモードを入れるとき(今回の範囲外とされた案)
