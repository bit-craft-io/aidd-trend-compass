# ADR-0002: 種類マスタのシーダーは、起動のたびに、全行を入れ替える

> **遡及作成(2026-10-08)**: 本ADRは、決定の後に、設計書と計画書の記述から書き起こした。仕様の本体は、設計書に有る(ここには書き写さない)。出典で確認できない点は「要確認」と記す。

## ステータス

提案中

## 背景・課題

種類マスタ `trend_system_type`(ADR-0001)の初期データを、開発・stage・運用で、どう入れるかを決める必要があった。

## 決定

- 開発・stage・運用で、同じやり方にする
- 起動のたびに(`python -m app.init_db` の中、`create_all` のあと)、全行を `TRUNCATE` して、初期データを、まとめて入れる(bulk insert)。MySQL は `TRUNCATE TABLE`、SQLite(テスト)は `DELETE`
- どの環境でも、マスタの内容と `id` が、同じになる
- マスタの行を DB で直しても、次の起動で、初期データに戻る。直すときは、シーダーの定義を直す

仕様の詳細: [設計書 10-trend-type-master.md](../design/10-trend-type-master.md)「シーダー」。確認の記録: [計画書](../superpowers/plans/2026-10-01-AIDDS-9-feature-improvement-202610-01.md) の「追記: AIDDS-10 の確認してほしい点」の4(確認済み)。

## 検討した代替案

- **足りない行だけ入れる**: 採らず。環境ごとに、マスタに差が出て、運用が複雑になるため(計画書 同上、設計書10「シーダー」)

## 影響・トレードオフ

- 起動のたびに、全行が入れ替わる。別のインスタンスが動いている間に起動すると、入れ替えの一瞬だけ、名称が `none` になりうる(一覧は表示される)
- DB でマスタを直す運用は、できない(次の起動で戻る)
- 世代管理用の列は、あとで追加する(今回は扱わない)。見直す兆候は、記録に無い(要確認)
