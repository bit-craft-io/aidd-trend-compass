# ADR-0006: 一覧のセレクトボックス・テキストボックスは、画面によらず、「ラベル+枠」で表示し、クリックで編集にする

> AIDDS-19 の仕様を、ユーザーが決めた直後に書いた(2026-10-19)。画面ごとの仕様は、設計書に有る(ここには書き写さない)。ここには、画面によらない、汎用的な判断だけを書く。

## ステータス

採用(2026-10-19、ユーザーが承認)

## 背景・課題

一覧の行の入力項目は、常に、入力欄(セレクトボックス・テキストボックス)として表示している。これを、値のラベル(枠線つき)で表示し、クリックしたときだけ、入力欄に切り替える形に変える。きっかけは、AIDDS-19(保有一覧)。

この判断を、保有一覧だけの個別の仕様にすると、画面が増えるたびに、同じ判断を、繰り返す必要がある。そこで、画面に依存しない一般則として決める(ユーザーの言葉: 「画面に依存せずで進められる」ため)。仕様の意図は、「一覧の、セレクトボックス・テキストボックスは、ラベル+枠で表示する。一覧以外は、通常の表示のまま。編集に入ったときの、入力の種類(テキストか、数値か)は、項目ごとに指定する。確定のタイミングは、種類ごとに固定にする」こと。

ラベル表示にしたい理由そのもの(動機)は、見た目(ユーザー)。

## 決定

- **対象**: 一覧(表の各行)の中の、セレクトボックスと、テキストボックス(数値の入力を含む)。どの画面の一覧かは、問わない
- **対象外**: 一覧以外(入力して、ボタンで実行するフォーム、画面の設定など)は、通常の表示のまま。一覧の中でも、チェックボックスなど、セレクトボックス・テキストボックス以外は、対象外
- **既存の一覧への適用**: どの一覧に、いつ適用するかは、画面ごとの設計書とタスクで決める。どの画面が適用済みかは、ここには書かず、設計書に書く
- **表示**: 値を、枠線つきのラベルで表示する。空は「—」。選択式で選ばれていない状態は、「未選択」に統一する
- **編集へ入る**: ラベルを、クリックする、または、Tab で着くと、その項目だけが、入力欄に切り替わる。セレクトボックスは、切り替えと同時に、`showPicker()` でリストを開く。対応しない環境では、2回クリックでよい
- **確定**: テキストボックスは、フォーカスが外れたとき、または、Enter で確定する(日本語入力の、変換の確定の Enter は、保存の確定にしない)。セレクトボックスは、値を選んだ時点で確定する。確定すると、ラベルに戻る。Esc は、取り消す
- **項目ごとの制御**: 編集に入ったときの、入力の種類(テキスト、数値(半角の数字だけ)、セレクト)は、項目ごとに指定する。確定のタイミングは、種類ごとに固定で、項目ごとに変える設定は、持たせない(使用者が戸惑うため)。保存は、確定したとき、呼び出し側が行う(保存の条件は、画面ごとに決める)
- **部品**: 表示と編集の切り替えは、共通の部品(`InlineEditField`)に持たせ、新しい画面でも、これを使う

画面ごとの仕様(数値欄の入力の制限、幅、保存の条件など)は、画面の設計書に書く。最初の適用: [設計書 06](../design/06-position-grouping.md)の末尾の節(AIDDS-19、保有一覧)。確認の記録: Jira AIDDS-19 の説明欄、[計画書](../superpowers/plans/2026-10-01-AIDDS-9-feature-improvement-202610-01.md)の Task 9。

## 検討した代替案

会話に出た案と、採った理由。理由が会話に無いものは、「要確認」。

- **画面ごとに、個別に決める**: 採らなかった。画面に依存せず、進められるようにするため(ユーザー)
- **一覧に限らず、すべてのセレクトボックス・テキストボックスに適用する**: 採らなかった。一覧以外(入力して、ボタンで実行する形など)は、通常の表示のままにする(ユーザー)
- **「保存される値の項目」で線を引く**: 私が示した案。ユーザーは、「一覧」で線を引く意図を示したので、採らなかった
- **一覧の行も、常時の入力欄のまま(現状)**: 採らなかった。見た目のため(ユーザー)。一覧以外が、通常の入力欄のままなのは、この案ではなく、決定の「対象外」
- **確定のタイミングを、項目ごとに、変えられる設定にする**: 採らなかった。項目ごとに異なると、使用者が戸惑うため(ユーザー)
- **セレクトボックスを、blur で確定する**: 採らなかった。選んだのに、枠が開いたままに見えるため(私が示した理由)
- **リストを開かず、2回クリックにする**: 採らなかった。クリックが、いまより1回増えるため。ただし、対応しない環境では、この形に落ちる(許容)
- **Tab で着いても、Enter を押すまで、編集に入らない**: 採らなかった。いまの、Tab で入力欄を渡る操作を、保つため(私が示した理由)

## 影響・トレードオフ

- 操作が、1段増える(クリックして、編集に入る)。対応しないブラウザでは、セレクトボックスが、2回クリックになる
- 一般則にしたので、一覧に、セレクトボックス・テキストボックスが増えたときも、この則に従う。一覧以外は、通常の表示なので、一覧と一覧以外で、入力の見た目が、異なる(意図した区別)
- 選択式の未設定の表示が、「未選択」に統一される。既存の文言(AIDDK-3 で決めた、グループの「選択」など)は、上書きされる
- 入力欄を直接触る、既存のテストを、「クリックして編集に入る」手順を足す形に、書き換える必要がある
- 見直す兆候: `showPicker()` に対応しない環境の利用が、増えたとき。一覧以外にも、同じ形にしたい要望が出たとき
