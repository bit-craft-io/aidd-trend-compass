# ADR-0003: トレンドの表示は、API が返す文字列を、そのまま出す

> **遡及作成(2026-10-08)**: 本ADRは、決定の後に、設計書と計画書の記述から書き起こした。仕様の本体は、設計書に有る(ここには書き写さない)。出典で確認できない点は「要確認」と記す。

## ステータス

提案中

## 背景・課題

保有一覧のトレンド列は、「上昇・下降・横ばい」と表示する仕様だった(設計書06・09の元の本文)。AIDDS-10 の差し戻し(Jira のコメントでの指摘。仕様漏れ)で、意図が示された: フロントは、API から送られてきた表示文字列を、そのまま表示する。フロント側に、名称を日本語に直す対応表を持たない(設計書10「追記: AIDDS-10 仕様漏れ」)。

## 決定

- 保有一覧と、発掘の一覧のトレンド列は、種類マスタの名前(`none` / `up` / `down` / `flat`)を、そのまま表示する。日本語への変換は、しない
- 判定なしは、`none` と表示する(値が無い、古い応答の `null`・未設定のときだけ、「—」)
- 発掘専用の日本語の対応表(`screeningTrendLabels.ts`)と、`TrendBadge` の `label` 引数は、廃止する
- 行の色・バッジの文字の色は、値で決める(従来どおり)

仕様の詳細: [設計書 10](../design/10-trend-type-master.md)の「追記: AIDDS-10 仕様漏れ」、[設計書 09](../design/09-trend-direction-and-market-colors.md)の末尾の節(AIDDS-17)。

## 検討した代替案

- **フロントで、日本語の対応表に直して表示する(従来)**: 採らず。意図(フロントに対応表を持たない)と合わないため(設計書10の追記)
- 表示の文字を、マスタで管理する案(AIDDS-16)は、この決定と矛盾しない。API が返す文字列が、マスタの表示名に変われば、画面は、その文字を、そのまま表示する。AIDDS-16 の採否は、記録に無い(要確認)

## 影響・トレードオフ

- 画面に、`up` などの英語が出る(日本語の「上昇・下降・横ばい」でなくなる)。見た目の分かりやすさより、API の文字列との一致を優先した
- 表示名を変えたいときは、マスタ側(API の返す文字列)を変える必要がある
